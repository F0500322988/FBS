# M189 — Student Agent دون لوحة إعدادات للطالب

المستخدم أكد وجود حساب ثابت على كل جهاز؛ لذلك يكون تجهيز DPAPI/Keychain مرة واحدة تحت ذلك الحساب، وتشغيل Agent عند تسجيل الدخول به.

## الحزم المعتمدة

Windows: https://github.com/F0500322988/FBS/releases/tag/m189-windows-3-1

macOS / iMac: https://github.com/F0500322988/FBS/releases/tag/m189-macos-3-1

يلزم تحديث تطبيق المعلم وأدوات تهيئته أيضًا حتى يصدر الحزمة المتوافقة مع Agent يعمل بالفعل في الخلفية. لا تحتوي المثبّتات العامة ملف lab-profile.json أو مفتاح المعمل الفعلي. يُنشئ المسؤول حزمة خاصة على المعلم وينفذ Setup-Student تحت حساب الطالب الثابت؛ ثم يعتمد الجهاز من المعلم. لا يكتب الطالب IP أو مفتاحًا أو بصمة.

## ما تغير

- Windows: ApplicationContext دون MainForm ظاهر، ولا لوحة أو أيقونة شريط مهام/صينية في التشغيل العادي. يُسجل المثبّت بدءًا تلقائيًا في HKCU للحساب الحالي ويبدأ Agent بعد التثبيت. لا يُنشئ اختصار إعدادات للطالب. عند غياب التهيئة ينتظر دون حوار ويعيد محاولة قراءتها.
- أُضيف طلب إيقاف منظم للـAgent الحالي للصيانة والإزالة، وتُغلق عمليته وطفل Node قبل حذف الملفات. لا تُحذف إعدادات المستخدم. لا تبدأ متابعة الجلسات إلا بعد تأكيد جاهزية وكيل الشبكة، وتعطل حالة الإدخال إذا فقد الجاهزية.
- Mac: تفعيل accessory/LSUIElement للطالب، دون Dock أو نافذة لوحة أو إعدادات عند التشغيل. تُقرأ Keychain دون طلب تفاعل في الخلفية؛ تُعالج التهيئة بواسطة المسؤول. ينتظر غير المهيأ بصمت ويلتقط ملف التهيئة عند وصوله.
- تثبيت LaunchAgent مسمى /Library/LaunchAgents/com.fbsclassroom.student.agent.plist لجلسة Aqua. تستخدم حزمة الطالب PKG جذرًا صحيحًا لتثبيت التطبيق وبند بدء الجلسة. يحتوي DMG الطالب على PKG كي لا يفوت تركيب بند التشغيل التلقائي.
- إعداد متقدم للمسؤول عبر --configure: تحقق صلاحيات مسؤول Windows، ومصادقة system.privilege.admin في Mac. لا يدخل هذا الوضع في التشغيل العادي. أدوات الحزمة الخاصة تبقى الطريقة المفضلة تحت الحساب الصحيح.
- تظهر نوافذ العمل الناتجة عن المعلم، مثل البث والرسائل والملفات، ومؤشرات الجلسة والأذونات اللازمة؛ لم تُلغَ موافقات التحكم أو اعتماد الأجهزة أو TLS.
- أُزيل شرط إغلاق التطبيق من import للحزمة؛ تظل قواعد رفض استبدال معلم أو مفتاح مختلف قائمة، وكذلك الكتابة الذرية وحفظ هوية الجهاز.

## التحقق الفعلي

مصدر التطبيقات وأداة التهيئة: 2a5036c، فرع build/m189-agent-r3.

- 1518 اختبار JavaScript محليًا، والمجموعة الكاملة نجحت في CI.
- مشاريع .NET الأصلية العشرة نجحت على Windows.
- بناء Mac Universal للمعماريتين، واختبارات AppKit السابقة، وتثبيت PKG وإزالته والتحقق من DMG نجحت على Intel.
- اختبار تشغيل تطبيق الطالب الفعلي على Mac بلا تهيئة سجل visibleWindows=0 وunconfiguredAgentWaitsWithoutSetup=true. هذا الاختبار لم يقرأ Keychain حقيقية.
- نجح bootstrap لبند LaunchAgent على جهاز CI وظهرت عملية قيد التشغيل، ثم bootout وإزالة ملفات الاختبار. لا يعادل ذلك تسجيل دخول/إعادة تشغيل جهاز المعمل الحقيقي.
- Windows: نجح تثبيت المعلم والطالب والتحقق من 528 و524 ملفًا وأيقوناتهما الرسمية. عمل Agent بلا نافذة، واستورد الحزمة وهو منتظر، ورُصد طفل Node بعد وصول التهيئة. نجحت إزالة البرنامج وبند التشغيل الخاص به وحفظ ملف غير تابع للحزمة.
- نُفذت 39 مراجعة لأداة التهيئة من كل مثبّت، وstudentBackgroundAgentVerified=true وstartupRegisteredAndRemoved=true في تقرير الطالب المنشور.
- استجابت روابط EXE وPKG الأربعة برمز HTTP 200.

## الحدود والتحديث

يغطي هذا الإصدار جلسة المستخدم بعد تسجيل الدخول، وليس خدمة SYSTEM/Daemon للتحكم قبل شاشة الدخول أو منعًا مطلقًا لإنهاء عملية يملكها المستخدم عبر النظام. يظهر التطبيق في أدوات النظام وقائمة البرامج المثبتة باسمه الحقيقي.

على Windows أزل النسخة القديمة بعد إغلاقها، ثم ثبّت الجديدة تحت الحساب الصحيح. على Mac أغلق التطبيق القديم وثبّت PKG، ثم جهز حزمة المعلم وأذونات الشاشة وإمكانية الوصول مرة واحدة بواسطة المسؤول. لا تحذف الإعدادات أو Keychain لتحديث البرنامج. أدوات الحزمة لا تستبدل إعداد معلم مختلف تلقائيًا؛ يحتاج إصلاح تهيئة قديمة غير صحيحة إلى تدخل المسؤول.

الحزم تجريبية: Windows دون شهادة توزيع، وMac بتوقيع محلي دون notarization. ARM64 بُني ولم يُنفذ على جهاز ARM في هذا التشغيل. لم يُختبر المعمل الفعلي أو إعادة تسجيل الدخول/الإقلاع الكاملة. تظل أذونات macOS ومؤشرات الجلسة قائمة، ويحتاج السلوك على الأجهزة الفعلية إلى تجربة المستخدم.
