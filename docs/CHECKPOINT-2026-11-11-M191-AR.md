## الإضافة

أيقونة «إضافة IP» في الشريط العلوي للمعلم تفتح نموذجًا عربيًا بخانتَي أول IP وآخر IP وزر Scan. تظهر أجهزة Agent التي أكدت اتصالًا حديثًا، مع Windows/macOS وحالة الاعتماد وزر «اعتماد الجهاز» للأجهزة غير المعتمدة. الإدخال يشمل العنوانين ويمكن وضع العنوان نفسه في الخانتين.

المسح موجّه عبر UDP إلى عناوين IPv4 الخاصة (10/8 و172.16/12 و192.168/16)، ثم يعتمد في نتائجه على هوية الطالب الموقعة عبر TLS، وليس مجرد استجابة ping أو منفذ مفتوح. يشمل حتى 1024 عنوانًا مع إرسال مضبوط، وحد زمني ومنع المسح المتزامن. الأجهزة المهيأة بعنوان معلم ثابت يمكن اكتشاف اتصالها الدوري أيضًا. لا يغيّر Scan إعدادات الطالب ولا يتجاوز مفتاح المعمل أو بصمة TLS. يلزم Agent مهيأ ومتاح عبر الشبكة؛ الجهاز المطفأ أو غير المهيأ لا يُضاف بعنوانه وحده.

واجهات المسح والاعتماد محمية بجلسة المعلم وفحص Origin. نتائج المسح لا تُرجع المفتاح العام أو أسرار المعمل. الاعتماد اليدوي يستخدم آلية حفظ الهوية الحالية. بروتوكول الطالب لم يتغير؛ يمكن استخدام Teacher M191 مع Student M190 المهيأ دون إعادة إدخال بياناته.

## التحقق المنفذ

- نجح 1524 اختبار JavaScript محليًا، دون اختبارات متجاوزة، بعد التعديل النهائي.
- اختبار فعلي اكتشف Agent تجريبيًا على عنوان خاص مملوك للبيئة باستخدام إعلان UDP موجّه واتصال TLS موقّع.
- اختبار قبول API فعلي مع تعطيل الاعتماد التلقائي: تسجيل دخول المعلم، مسح عنوان الاختبار، ظهور الطالب غير معتمد، اعتماده يدويًا وحفظ اعتماده، وعدم كشف مفتاحه العام في استجابة المسح.
- اختبارات النطاقات: العناوين غير الصالحة والعامة والمعكوسة والزائدة، وشمول الطرفين، ورفض السجلات القديمة وخارج النطاق، ومنع التزامن وإزالة القفل عند الفشل.
- اختبار Chromium/Playwright للواجهة: فتح النافذة وإدخال النطاق وعرض النتائج والاعتماد اليدوي وحالة الخطأ ومسح النتائج السابقة والإغلاق، دون أخطاء صفحة. واجهة API في هذا الاختبار محاكاة؛ اختبار UDP/TLS وAPI الفعلي منفصل.
- تقارير الاختبار ولقطة واجهة الاختبار في `/workspace/outputs/M191-IP-Scan`.
