# تجربة FBS Classroom على ويندوز

هذه نسخة تطوير. بيانات وضع العرض تجريبية وليست أجهزة طلاب حقيقية.

## عرض اللوحة على جهازك

1. فك ضغط المشروع في مجلد محلي.
2. ثبّت Node.js إصدار 22 أو 24 من موقعه الرسمي إذا لم يكن مثبتًا.
3. افتح PowerShell داخل المجلد الذي يحتوي على `server.js`.
4. نفّذ:

```powershell
$env:FBS_DEMO='1'
node server.js
```

5. بعد ظهور رسالة بدء الخادم، افتح المتصفح على `http://127.0.0.1:4177` على الجهاز نفسه.
6. تحقق من ظهور 21 جهازًا تجريبيًا، منها 20 متصلًا، ثم جرّب صفحة مراقبة الأجهزة ومخطط المقاعد.
7. لإيقاف الخادم، اضغط Ctrl+C في نافذة PowerShell.

## فحوص المطوّر

ثبّت .NET 8 SDK لتشغيل الفحوص التالية من مجلد المشروع:

```powershell
Remove-Item Env:FBS_DEMO -ErrorAction SilentlyContinue
node --test tests/*.test.js
dotnet run --project windows/FBS.NativeGate.Tests/FBS.NativeGate.Tests.csproj
dotnet build windows/FBS.Teacher.Launcher/FBS.Teacher.Launcher.csproj
```

بناء مشروع المعلم يبني مشروع الطالب أيضًا. فحوص JavaScript تشمل فحوصًا نصية؛ نجاحها لا يثبت التشغيل على ويندوز أو الشبكة.

## نتيجة المتابعة الحالية

- نجحت استعادة الملفات والأدوات من البيئة المنشورة، دون إعادة تطبيق إصلاحات الواجهة السابقة.
- صُحح اختبار عدّاد سجل الجلسة: قرار الرفض قبل بدء الجلسة لا يدخل في عدّاد جلسة جديدة. أُضيفت فحوص صريحة للتصفير عند البدء والإيقاف.
- اكتملت مجموعة اختبارات C# الأصلية بنجاح، بما فيها الفحوص التي لم تكن تصل إليها سابقًا.
- نجحت اختبارات JavaScript وعددها 1426.
- نجح بناء المعلم والطالب على Linux مع استهداف Windows. لم يُشغّل برنامجا Windows Forms هنا.
- لم تُنشر تغييرات جديدة ولم تُرفع الملفات إلى GitHub.

## اختبار أجهزة المعمل الحقيقي

الخطوة التالية تجربة جهاز معلم وجهاز طالب بويندوز، وفق `M167-START-HERE.md`، بما يشمل الاعتماد والشهادات وانقطاع الشبكة وإعادة الاتصال. هذا يحتاج الجهازين وإعداد هوياتهما، ولا يمكن إثباته ببيانات العرض التجريبية.

التحكم بالفأرة ولوحة المفاتيح وبث الشاشة وتوزيع الملفات ليست ميزات مكتملة في هذه النسخة. ملفات المصدر ليست حزمة تثبيت نهائية.
